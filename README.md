# Orbit Reader for Android

An independent native Android client for a self-hosted BookOrbit server. It supports audiobook playback and EPUB, PDF, comic, FB2, and DRM-free MOBI reading, without claiming iOS feature parity or official BookOrbit endorsement.

This is a standalone Android project. It builds from this repository's root and connects to an existing BookOrbit server over HTTP. A BookOrbit source checkout, Node.js, pnpm, and a local PostgreSQL database are not required.

## Build and install

For APK downloads without a Play Store account, use this repository's
[GitHub Releases](https://github.com/Nebularc18/Orbit-Reader/releases) when a release
is available. See [GitHub APK releases](docs/RELEASING.md) for signing setup,
publishing, and installation instructions.

Requires JDK 17 and Android SDK platform 35 with build tools 35.0.0. Open this directory in Android Studio, or set `JAVA_HOME` and `ANDROID_HOME` and run:

```sh
./gradlew spotlessCheck :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

The Gradle wrapper includes a distribution checksum. SDK paths belong in an untracked `local.properties` or `ANDROID_HOME`.

Use the server's root URL, including its reverse-proxy path if present. A trailing `/api/v1` is accepted. HTTPS is preferred. HTTP is supported for trusted local servers with an explicit message on the sign-in screen. Normal certificate validation stays enabled. Password sign-in is available when enabled on the server. For OIDC, enter the server address, choose Load sign-in options, and select a provider. Provider sign-in opens the system browser and creates a native refresh session. For a magic link, enter the server address, choose Use a magic link, and paste its link or token. Links must belong to that server; tokens are passed directly to the server and cleared from the input field. Magic-link sessions retain and rotate the server refresh cookie in encrypted storage, sending it only to refresh and logout endpoints.

## Provider sign-in

OIDC uses BookOrbit's public login-options and provider-state APIs, PKCE with S256, a fresh nonce, and an exact callback-state check. Pending sign-ins are encrypted with Android Keystore, expire after ten minutes, and are consumed once before exchanging the code. A callback cannot switch accounts after the active account has changed. Existing saved connections remain available. Interrupted exchanges require starting sign-in again.

The server and identity provider must both allow `bookorbit://oauth2-callback`, BookOrbit's default native redirect URI. If the server overrides `NATIVE_REDIRECT_URI`, it must use that exact value for this client. If another app also handles that scheme, choose Orbit Reader in Android's app chooser. Provider authorization endpoints require HTTPS, except a same-origin HTTP endpoint on a trusted local HTTP server. No identity-provider secret is stored in the app. Servers without the login-options endpoint can still use password sign-in.

## Uploads and metadata

Open Upload a book from Home, select a permitted library and optional folder, then choose a file using Android's document picker. The server supplies supported formats and size limits. Uploads stage a private copy, use checksummed resumable chunks, and run through WorkManager with the account's Wi-Fi preference and shared two-transfer limit. Pause retains progress; Resume checks the server offset before continuing. Completed tasks report server completion. Remove local task deletes the staging copy and local task only; bytes already received by the server remain subject to its retention rules. A failed or expired server task requires selecting the file again. Up to 30 tasks are retained per account. Library upload permission and a server with the resumable upload API are required.

Book details offers Edit metadata to accounts with metadata permission. The grouped editor covers book fields, authors, genres, tags, provider identifiers, series memberships, community ratings, audiobook narrators/timings, comic credits, and existing custom-field values. Only changed fields are sent. Before saving, the app re-reads edited fields and refuses detected conflicts; the server has no conditional metadata write, so simultaneous writes can still race. Shared fields can affect other users and server book files; series totals apply across the series. Cover management, custom-field definitions, metadata locks, and bulk administration remain in the web client.

## Home-screen widget

Add Orbit Reader from Android's widget picker for Home, Listen, Read, and Downloads shortcuts. The widget opens the active account in the app, or sign-in when disconnected. It stores no credentials or book metadata and never starts playback by itself.

## Tablet layouts and accessibility

At window widths of 600 dp or more, the app uses a navigation rail. Main content stays within 1200 dp, and the player controls within 640 dp. Catalog covers grow on wider screens; larger system text reduces grid density. Phone windows keep the bottom tabs. Appearance settings scroll when space is limited. Search fields have persistent labels, screen headers expose accessibility headings, and the shared icon actions and time-display toggle have 48 dp touch targets. EPUB and page-reader controls stay visible while Android touch exploration is enabled.

TalkBack checks cover reader controls, EPUB text, page-text dialogs, and named narration-speed controls on the Android 15 emulator. PDF, FB2, and MOBI offer Page text for screen-reader access to their text layer. Reader controls stay visible during keyboard navigation, and pages fit below the visible toolbars. An Android 9 tablet emulator passed sign-in, navigation-rail, catalog, and keyboard checks; its PDF text engine passed a direct compatibility check. Full gesture testing on that emulator was interrupted by Android system and automation crashes. Physical tablets, stable older-device gesture checks, and broader spoken-output and keyboard coverage remain follow-up work.

## Book requests

Open Book requests from Home to submit an ebook or audiobook title with an optional author and note. Your account needs BookOrbit's `book_request_access` permission, and the server must support the book-request API. Requests use the server's approval, availability, duplicate-joining, and quota rules. The personal list shows requests made or joined by the account, with server-side status and format filters and 30-entry pages. Eligible requests you own can be cancelled after confirmation, including a warning that cancellation can stop an active transfer.

Requests require a connection. Submissions are never queued offline or retried automatically after a transport failure; refresh the personal list before resubmitting when the result is uncertain. Provider metadata search, request pairs, destination selection, moderation, and download administration remain available through BookOrbit's web client.

## Multiple servers

Connect multiple BookOrbit servers and switch between them from the server name on Home, or Appearance and account → Servers. Add server signs in to another server without signing out of existing connections. Libraries stay separate. The switcher identifies each connection by address and username; choosing one makes it the active library. Playback pauses and persists its position before switching. Queued downloads and sync jobs wait while their account is inactive and retain account checks before API calls. Downloads, progress, covers, appearance, and catalog preferences remain scoped to the server and account.

Saved access/refresh tokens share the Android Keystore encrypted session store and remain excluded from backup and device transfer. Existing single-server sign-ins migrate automatically. Sign out disconnects only the active connection and returns to another saved server when available; its downloaded files stay private for a future sign-in to the same account.

## Library and activity

Library groups books by Series, Authors, Collections, and Shelves. Shelves are the saved smart scopes from BookOrbit. Series and author search and ordering run on the server with 30-item pages and a bounded 150-item window. The server currently returns collection and smart-shelf metadata as lists; these are searched and paged locally. Opening a group retrieves its books in bounded pages, with series in volume order. Each book opens its information sheet with Read and Listen actions for its supported files.

Home links to Activity, which shows server-recorded reading and listening time, current and longest streaks, annual goal progress, daily activity, monthly completions, source distribution, and weekly session history. Weeks can be browsed backward and forward through the current week. Unsupported activity endpoints show an explanation and retry instead of invented statistics. App tabs crossfade, catalog controls adapt to available width, and the shared loading, empty, and error views keep navigation consistent.

## Book tools and playback preferences

Book information includes account reading status, a personal rating (when the account has metadata permission), and membership in owned collections. Changes use BookOrbit's server APIs and refresh the cached detail. Audiobook details offer Play next and Add to queue. Appearance and account → Playback & downloads opens the account-scoped queue and preferences.

Smart resume is optional: after a pause of at least a minute, rewind by 5, 10, 15, or 30 seconds. Manual seeking preserves the chosen position. Queue autoplay and next-in-series continuation are separate opt-in settings. The queue takes priority when autoplay is enabled. Progress conflicts still require review on the phone before playback continues.

Offline preferences include Wi-Fi-only downloads, a per-account storage limit, optional Wi-Fi prefetch of the next queued or series audiobook, and optional removal of finished audiobook audio. Storage limits block further downloads without deleting existing books. Finished cleanup retains bookmarks, manifests, and listening positions. All automatic playback and deletion options start disabled.

Notes and audiobook bookmarks can be exported as Markdown or plain text through Android's file picker. Exports include human-readable passages, notes, and bookmark times; account credentials and internal locators are excluded.

Android Auto can browse Continue listening, Downloaded books, Listening queue, and a paged audiobook catalog, with search and server-scoped book selection. Sign in and select the active server on the phone first. A physical head unit or Desktop Head Unit remains necessary to verify the car interface.

EPUB/KEPUB read-aloud uses installed offline Android speech voices, with speed, voice selection, sentence navigation, and sentence highlighting. It reads the open chapter and pauses when leaving the reader. Open the next chapter to continue. PDF/comic read-aloud, background speech controls, and synchronized Read Along are not included.

## Notebook

Open Notebook from Home to browse highlights, reading notes, ebook bookmarks, and audiobook bookmarks saved on this device for the active server account. Search matches words across book titles, authors, entry names, quoted passages, and notes. All, Highlights, Notes, and Bookmarks filters combine with search. Results use 30-entry pages, ordered by ebook file ID followed by audiobook ID, with saved entry order within each file or book. Only one page and one file's annotations are held while searching.

Open an entry to read or copy its full text, edit a reading note, rename a bookmark, or delete its local copy with confirmation. Reading entries can be exported as Markdown or plain text. Go to passage opens the saved EPUB, PDF, or comic location when its matching file is on device. Entries from changed or removed files remain readable, but cannot navigate until matching content is available. Open audiobook opens its information sheet; playback remains an explicit action. Shared server annotations are kept when a local entry is edited or deleted. Notebook refreshes when returning from a reader and never publishes notes or progress automatically.

## Ebook and comic reading

Orbit Reader uses an ink background and brass accents with compact headers, outlined panels, and a floating Home/Listen/Read/Downloads bar. Appearance and account settings are available from the sliders icon: choose System, Light, or Dark and a Brass, Sage, or Ocean finish. Preferences are stored per server account. The dashboard shows one resume card without duplicating that book in its shelves. A Your reading panel uses BookOrbit's reading-goal and streak widgets when available; unsupported endpoints hide the panel. Both catalogs support three-column cover grids and compact list views, server search, and infinite scrolling. Use the sort control below search to order by title, author, date added, series, publication date, or your rating. Title and author support both directions. The adjacent reading-status menu filters the online catalog to Unread, In progress, Finished, On hold, Skimmed, or Abandoned. Unread includes books marked Unread or Want to read; their individual server statuses remain separate. These use the server account status, including web updates, and remain combined with search and sorting. Each catalog remembers its status filter; All books clears it. Sorting applies on the server before pagination, and each server account remembers separate choices for Listen, Read, and their offline views. Offline shelves sort all saved book metadata by title or author before slicing pages, retaining only lightweight metadata for the full sort. Tap an ebook to read or long-press for options. Book details place the cover beside the title and authors, with synopsis and grouped metadata below. The mini-player includes a separate play/pause control. The full player uses cover-derived ambient color, both timelines, chapter navigation, bookmarks, and a sleep timer. Skip intervals are under More playback options. Covers retain their original proportions and rounded corners.

Home is the opening screen, with Continue listening, Continue reading, and Next in series. The optional reading panel makes two account-scoped GET requests to `dashboard/widgets/reading-goal` and `dashboard/widgets/reading-streak`. Each section requests at most ten books from BookOrbit's dashboard API. Continue listening follows the server shelf after a successful refresh, so books completed on another device disappear. If the server cannot be reached, it falls back to account-scoped listening history from this phone. Continue reading combines local activity with server results, with local recency first and refreshed server metadata when available. Returning to the dashboard or the app refreshes its sections. Next in series follows the server's recommendations and offers Read or Listen according to the available file formats. A section that cannot refresh retains local activity and offers a retry. Ebook resume entries require saved content and a matching reading-position revision. Reading positions sync automatically through account-scoped background work. Reading-time sessions are not reported yet.

Library and download lists load additional 30-book pages as you scroll, with a 150-book memory window and retry controls for failed loads. Search and media filtering remain on the server. Earlier pages load again when scrolling back. Audiobook cards and dashboard audiobook actions open the same expanded details sheet without starting playback. The sheet shows cover art, synopsis, series, publisher/publication date, language, pages, ISBNs, rating, reading status, genres, tags, collections, personal notes, and available files where the server provides them. Book information is cached per server account for offline use. Ebook information is available through its long-press options; tapping an ebook still opens the reader.

The Read tab shows authenticated cover thumbnails and lists EPUB, KEPUB, PDF, CBZ, CBR, and CB7 files using bounded server-side search. Tap a book to start reading and keep an account-scoped offline copy. Long-press a book for file choices and download removal. The reader remembers the last file chosen for each book. Use On device to reopen saved files. Download removal preserves local reading positions and notes for the same file revision.

Reader controls start hidden. Tap the middle of the page to show or hide the top and bottom controls; they also hide after six seconds. Tap the left or right quarter of the screen to turn pages, or swipe. Controls overlay the page without changing its layout. Android Back returns to the library even while controls are visible; in PDF selection mode, it cancels selection first. Text selection and PDF zoom gestures remain available. Highlight without a selection shows a temporary hint.

EPUB and KEPUB use [Readium Kotlin](https://readium.org/kotlin-toolkit/3.1.0/), with contents, paging, scrolling, text size, and light, sepia, or dark themes. Bookmark saves a reading location with a name and optional note. Select text and choose Highlight to save a highlighted passage. Notes lists saved passages, offers jumping, editing, and deletion, and disables locations from changed file revisions. Notes and highlights are saved locally for each server account, with up to 500 entries per file. Share annotation explicitly publishes a located passage. Server annotations lists 25 entries per page and supports importing offline copies, editing server notes, and deleting server annotations with confirmation. Sharing checks the file revision. Imported copies and server annotations are managed separately; local edits do not automatically publish, and server deletion retains offline copies. A failed create can have an uncertain result, so check the server list before retrying.

PDF uses Android's native PdfRenderer. CBZ images are read directly from ZIP archives in natural numeric order. CBR and CB7 use BookOrbit's authenticated page-conversion API to prepare an offline ZIP copy. These readers render one page at a time, support pinch zoom and panning, Fit, Zoom +, previous/next pages, page jumps, bookmarks, and page notes. Images are decoded to a bounded size. Encrypted PDFs and image codecs unsupported by the device cannot be read. PDF Highlight area lets you drag a rectangle, add a note, and keep the mark offline or share its page geometry with BookOrbit. Marks follow page zoom and panning. Select text uses MuPDF source-text extraction on Android 8 and newer: tap a word or drag across a passage, then copy it or save a text highlight and note. Multi-line highlights keep separate rectangles. Scanned pages without a text layer retain area highlighting. PDF rendering continues through Android's PdfRenderer. Page text opens the current PDF, FB2, or MOBI page's text layer as selectable text for screen readers and keyboard users, showing at most 32,000 characters. Scanned pages explain when no text layer is available.

FB2 and DRM-free MOBI open in the page reader through [MuPDF](https://mupdf.readthedocs.io/en/latest/guide/what-is-mupdf.html), distributed under AGPLv3 or later. They use a fixed local layout with page navigation, zoom, bookmarks, and local position restoration. Their shared progress uses percentage because renderer page numbers are not portable. AZW/AZW3, DJVU, DRM-protected books, and reflowable font/theme controls for FB2/MOBI are not supported.

Read Along in the EPUB toolbar plays a chapter's embedded narration when the EPUB contains SMIL media overlays. It follows timed text anchors with a yellow highlight, offers previous/next segment and speed, and remembers the last segment for the file revision. Leaving the reader or changing chapters pauses playback. Chapters without supported timing data explain why playback is unavailable. Read Along does not manufacture alignment for a separate audiobook. Narration extraction is limited to 32 MB per audio resource and 128 MB per chapter; it plays while the reader is foregrounded.

Reading positions save locally and queue account-scoped WorkManager sync during reading, when leaving the reader, and when the app goes to the background. Pending uploads survive process death and retry after connectivity returns. Android force-stop prevents background work until the app is opened again; an abrupt kill can miss the last location callback. The worker verifies the file revision and compares server progress with the last known snapshot before writing. Changed server progress pauses automatic uploads for review in Sync. A first open without a server snapshot also requires review before publishing. BookOrbit has no conditional ebook write, so simultaneous updates can still race between the check and write. Sync offers Refresh server progress, Use server position, and Publish this position to resolve conflicts explicitly. These operations sync position only; reading-time session reporting is not implemented. EPUB sharing includes source CFIs when a location can be resolved, while PDF and comics share page numbers. Source paths are retained through sanitization, and selected text also captures exact range offsets. Incoming CFIs are resolved against the saved EPUB before navigation. Unsupported or ambiguous CFIs fall back to percentage, with a message; the dialog identifies when only a percentage can be published. A publish replaces the server's text position, including its prior CFI. CFI side-bias parameters are accepted at source boundaries. CFIs with temporal/spatial positions and automatic annotation merging are not supported.

Downloads use bounded buffers and the shared limit of two concurrent media transfers. Interrupted downloads restart. Limits are 512 MB per saved book, 20,000 archive entries or pages, 32 MB per expanded resource, and 1 GB total expanded archive size. EPUB scripts and active elements are removed before Readium adds its own controls; remote resources and external links remain blocked. Saved books and credentials are excluded from backup and device transfer. Release packaging remains deferred.

## API contract

The upstream API contracts are defined by [BookOrbit's shared types](https://github.com/bookorbit/bookorbit/tree/main/packages/types/src) and [server modules](https://github.com/bookorbit/bookorbit/tree/main/server/src/modules). `app/src/main/java/app/bookorbit/community/data/Models.kt` contains the Kotlin wire projections used by this client. Unknown response fields are tolerated. Request fields are explicit because the server rejects unknown DTO fields. No local dependency on the BookOrbit monorepo is required. Audiobook playback requires the server's v2 audiobook manifest API.

| Request                                      | Contract                                                                                                            |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `POST auth/login`                            | `username`, `password`, `clientKind: native`, `deviceLabel`; reads `user`, `accessToken`, `refreshToken`            |
| `POST auth/refresh`                          | Body refresh token; atomically saves rotated credentials; retries a rejected request once                           |
| `POST auth/logout`                           | Body refresh token; clears local credentials even if revocation fails                                               |
| `POST books/query`                           | `BookQuery`, format and optional readStatus filters, server search and sorting, 30-item pages; displayed page 1 maps to server page 0; reads `BooksPage.items/total/page/size` |
| `POST auth/magic-links/login` | Token-only exchange; access token/user in JSON and refresh session in Set-Cookie |
| `GET uploads/capabilities`, `POST uploads` | Permission/size/format discovery and an idempotent library-target session |
| `GET uploads/:id`, `POST uploads/:id/chunks`, `POST uploads/:id/complete` | Authoritative offsets, bounded multipart file chunks, SHA-256 checksums, and processing status |
| `PATCH books/:id/metadata` | Changed DTO fields only, after re-reading edited values to detect conflicts |
| `GET books/:id`                            | Ebook file IDs, formats, sizes, and content revisions from the existing book detail model                              |
| `GET books/files/:fileId/serve`              | Authenticated EPUB reading content, kept in account-scoped local storage                                               |
| `GET audiobooks/:id/manifest`                | Audiobook manifest v2, with assets ordered by sequence                                                              |
| `GET audiobooks/:id/assets/:assetId/content` | Authenticated, ranged streaming                                                                                     |
| `GET books/files/:fileId/download`           | Download permission enforced by the existing server; UI checks the account permission too                           |
| `POST books/files/:fileId/sessions` | Active listening duration, stable session UUID, timestamps, `sessionType: listen`, and `source: android` |
| `GET/PUT audiobooks/:id/playback-state`      | Asset-relative milliseconds, manifest revision, base revision, capture time, and stable operation UUID              |

All paths use `/api/v1`. Access tokens stay in headers. The HTTP client rejects cross-origin credential forwarding and does not follow redirects. Reverse proxies should route the API directly rather than redirecting it. Library ownership and content access remain enforced by the existing backend.

Progress saves occur every five seconds while connected and every ten seconds while offline, on pause, on seeks, and during orderly service shutdown. Abrupt process termination can lose the last interval. Offline work is retried when connectivity returns. A changed manifest returns 412 and needs a fresh download; conflicts return 409 and are never automatically rebased. Download assets are length-checked when the server provides a size. Download requests use identity encoding, Range, and If-Range when a saved strong HTTP ETag is available. The client verifies Content-Range, validators, and lengths before appending or completing an asset. Servers without this support restart unfinished assets. BookOrbit v3.4.0 ignores ranges on its download endpoint and omits ETag, so it uses this safe restart behavior. File integrity hashes, pre-download space estimates, and cleanup of obsolete revisions remain follow-up work.

Listening time is tracked by the playback service, including background and downloaded playback. It uses elapsed real time, so speed changes and seeks do not add listening time; pauses and buffering close the active session. Sessions follow the current audio file and rotate after five minutes. At each progress capture, sessions of at least ten seconds are saved atomically under the server/account and queued separately from position sync. BookOrbit ignores sessions shorter than ten seconds. Retries reuse the same session UUID; the current server accepts longer checkpoints for that UUID without counting the earlier checkpoint twice. An independent periodic drain covers uploads that race with a new checkpoint. Pending sessions survive app restarts and wait for their account to be active. Abrupt termination can lose the final capture interval. Earlier missing history cannot be reconstructed from saved positions alone.

## Emulator verification

On October 19, 2026, the Android 15 Pixel 9 Pro emulator passed password sign-in, library browsing, two-file streaming, chapter selection, speed selection, sleep-timer configuration, complete-book download, and offline playback after restarting the app with its server connection removed. Playback continued while the screen was asleep and advanced to the second file. Android's media-pause command paused playback, and progress synchronized after reconnecting. The player was changed to open fully expanded so playback controls are visible immediately.

The end-of-book Play action was also fixed and verified to restart playback from the first file. The updated APK was installed and left on the emulator with the synthetic library available.

Separate chapter and whole-book timelines were subsequently verified on the same emulator. A whole-book seek to 0:20 selected the second file at 0:00, and a chapter seek to 0:10 moved the whole-book position to 0:30. Seven timeline tests cover cross-file chapters, exact boundaries, clamping, chapter markers, and unknown durations.

## Listening preferences and bookmarks

The player has Bookmarks and Skip intervals controls. Bookmarks save the current audio file and position, with an editable name up to 120 characters. Tap a bookmark to seek without changing whether playback is paused. Each book supports up to 500 bookmarks. If its manifest changes, old bookmarks remain visible for renaming or deletion, but cannot seek into different audio.

Playback speed is saved separately for each book. Back and forward intervals offer 5, 10, 15, 20, 30, 45, or 60 seconds, with defaults of 15 and 30. The intervals apply to all audiobooks for that account, including Android media controls. Skips cross file and chapter boundaries when file durations are known. With unknown durations, skips stay in the current file and clamp to its length when available.

Bookmarks, speed, and skip intervals are local to this device and scoped to both server and account. They survive app restarts and download removal. They do not synchronize to BookOrbit or other devices. Production release signing and the update channel remain pending. A signed debug APK is available for phone testing.

## Repeatable smoke fixture

```sh
python3 scripts/fixture-server.py --port 4890
adb reverse tcp:4890 tcp:4890
```

Sign into `http://127.0.0.1:4890` with the fixture-only username and password `reader`. It provides synthetic two-part audio, a two-chapter EPUB, a three-page PDF, a three-page CBZ, an FB2 book, EPUB SMIL narration, upload/metadata endpoints, magic-link sessions, and converted-comic endpoints. It is a synthetic test library. The Read tab lists the reading fixtures; its On device view can be exercised with the fixture stopped. Check search, playback while backgrounded, chapters, speed, downloads, and offline relaunch after stopping the fixture. Never deploy the fixture as a BookOrbit server.

Add `--oidc --requests-count 65` to enable a synthetic browser sign-in provider and a paged request list for testing. This provider accepts no real identity credentials and is fixture-only.

For extra ebook verification, pass `--ebook-file /path/outside/repository/book.mobi` (up to three files). The fixture serves copies of supported DRM-free books only through authenticated ebook endpoints. `--upload-delay-seconds 1` makes chunk responses slow enough to test pause and restart recovery. Magic-link tests use the fixture-only token `fixture-magic`.

For private real-audiobook previews, pass `--book-dir /path/to/private-fixture`. That directory must contain a v2 `manifest.json`, `cover.jpg`, and one `<fileId>.<format>` file per manifest asset. Supported fixture formats are M4B, M4A, and MP3. File responses stream in bounded chunks and support byte ranges. Keep audiobook copies and their metadata outside the repository. Playback progress stays in the test server rather than reaching your production library.
