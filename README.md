# Orbit Reader for Android

An independent native Android client for a self-hosted BookOrbit server. It supports audiobook playback and an initial EPUB reader, without claiming iOS feature parity or official BookOrbit endorsement.

This is a standalone Android project. It builds from this repository's root and connects to an existing BookOrbit server over HTTP. A BookOrbit source checkout, Node.js, pnpm, and a local PostgreSQL database are not required.

## Build and install

Requires JDK 17 and Android SDK platform 35 with build tools 35.0.0. Open this directory in Android Studio, or set `JAVA_HOME` and `ANDROID_HOME` and run:

```sh
./gradlew spotlessCheck :app:testDebugUnitTest :app:lintDebug :app:assembleDebug
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

The Gradle wrapper includes a distribution checksum. SDK paths belong in an untracked `local.properties` or `ANDROID_HOME`.

Use the server's root URL, including its reverse-proxy path if present. A trailing `/api/v1` is accepted. HTTPS is preferred. HTTP is supported for trusted local servers with an explicit message on the sign-in screen. Normal certificate validation stays enabled. Password login must be enabled on the server. OIDC and magic-link sign-in are pending.

## Multiple servers

Connect multiple BookOrbit servers and switch between them from the server name on Home, or Appearance and account → Servers. Add server signs in to another server without signing out of existing connections. Libraries stay separate. The switcher identifies each connection by address and username; choosing one makes it the active library. Playback pauses and persists its position before switching. Queued downloads and sync jobs wait while their account is inactive and retain account checks before API calls. Downloads, progress, covers, appearance, and catalog preferences remain scoped to the server and account.

Saved access/refresh tokens share the Android Keystore encrypted session store and remain excluded from backup and device transfer. Existing single-server sign-ins migrate automatically. Sign out disconnects only the active connection and returns to another saved server when available; its downloaded files stay private for a future sign-in to the same account.

## Library and activity

Library groups books by Series, Authors, Collections, and Shelves. Shelves are the saved smart scopes from BookOrbit. Series and author search and ordering run on the server with 30-item pages and a bounded 150-item window. The server currently returns collection and smart-shelf metadata as lists; these are searched and paged locally. Opening a group retrieves its books in bounded pages, with series in volume order. Each book opens its information sheet with Read and Listen actions for its supported files.

Home links to Activity, which shows server-recorded reading and listening time, current and longest streaks, annual goal progress, daily activity, monthly completions, source distribution, and weekly session history. Weeks can be browsed backward and forward through the current week. Unsupported activity endpoints show an explanation and retry instead of invented statistics. App tabs crossfade, catalog controls adapt to available width, and the shared loading, empty, and error views keep navigation consistent.

## First milestone

- Native Kotlin and Jetpack Compose screens, with light and dark themes.
- Password sign-in using native refresh sessions. Credentials are encrypted with an Android Keystore key and excluded from backup.
- Server-side audiobook search and filtering, in pages of 30. The client keeps one page in memory.
- Multi-file audio, chapters, background playback, audio focus, headset disconnection handling, and Android media controls through Media3.
- Configurable rewind and forward intervals, playback speed remembered per book, named bookmarks, and a sleep timer with timed and End of chapter options. The chapter timer follows the selected chapter boundary across audio files and playback-speed changes. Pausing playback retains the chapter target; seeking past it pauses playback, and opening a book clears the chapter timer. Separate chapter and whole-book timelines use thin continuous tracks and round handles. The whole-book right-hand time defaults to remaining media time; tap it to switch to total duration. This preference is saved per server account. The chapter track retains its elapsed and total times. Both timelines seek across audio files when durations are available. The chapter list highlights the current playback chapter and opens with that row in view; its full-width touch targets keep equal side padding.
- Complete-book downloads through foreground WorkManager jobs, with at most two books transferring concurrently. Wi-Fi-only is the default. Files stream through a 64 KiB buffer. Progress shows the percentage and transferred/total bytes across all files, including files completed before a retry. Unknown sizes remain indeterminate until their lengths are known. Pausing and interruptions retain partial audio and completed assets. Partial files resume with byte ranges and a strong HTTP validator when the server supports them; otherwise the unfinished asset restarts safely. Temporary server failures retry automatically.
- Offline playback from private app storage, scoped by server and account.
- Local listening positions and queued, revision-checked server updates. Conflicts require an explicit choice between this device and the server.

Android Auto, Wear OS, widgets, listening statistics, and Read Along are pending. Audiobook bookmarks are implemented. The Downloads tab shows complete and unfinished downloads, account-scoped audio storage usage, and device free space. Resume, retry, pause, and removal are available on the book sheet. Removal is disabled for the active audiobook. Downloads are retained on sign-out and can only be browsed after signing back into the same account.

## Ebook and comic reading

Orbit Reader uses an ink background and brass accents with compact headers, outlined panels, and a floating Home/Listen/Read/Downloads bar. Appearance and account settings are available from the sliders icon: choose System, Light, or Dark and a Brass, Sage, or Ocean finish. Preferences are stored per server account. The dashboard shows one resume card without duplicating that book in its shelves. A Your reading panel uses BookOrbit's reading-goal and streak widgets when available; unsupported endpoints hide the panel. Both catalogs support three-column cover grids and compact list views, server search, and infinite scrolling. Use the sort control below search to order by title, author, date added, series, publication date, or your rating. Title and author support both directions. The adjacent reading-status menu filters the online catalog to Unread, In progress, Finished, Want to read, On hold, Skimmed, or Abandoned. These use the server account status, including web updates, and remain combined with search and sorting. Each catalog remembers its status filter; All books clears it. Sorting applies on the server before pagination, and each server account remembers separate choices for Listen, Read, and their offline views. Offline shelves sort all saved book metadata by title or author before slicing pages, retaining only lightweight metadata for the full sort. Tap an ebook to read or long-press for options. Book details place the cover beside the title and authors, with synopsis and grouped metadata below. The mini-player includes a separate play/pause control. The full player uses cover-derived ambient color, both timelines, chapter navigation, bookmarks, and a sleep timer. Skip intervals are under More playback options. Covers retain their original proportions and rounded corners.

Home is the opening screen, with Continue listening, Continue reading, and Next in series. The optional reading panel makes two account-scoped GET requests to `dashboard/widgets/reading-goal` and `dashboard/widgets/reading-streak`. Each section requests at most ten books from BookOrbit's dashboard API. Continue listening follows the server shelf after a successful refresh, so books completed on another device disappear. If the server cannot be reached, it falls back to account-scoped listening history from this phone. Continue reading combines local activity with server results, with local recency first and refreshed server metadata when available. Returning to the dashboard or the app refreshes its sections. Next in series follows the server's recommendations and offers Read or Listen according to the available file formats. A section that cannot refresh retains local activity and offers a retry. Ebook resume entries require saved content and a matching reading-position revision. Reading activity remains local unless explicitly shared.

Library and download lists load additional 30-book pages as you scroll, with a 150-book memory window and retry controls for failed loads. Search and media filtering remain on the server. Earlier pages load again when scrolling back. Audiobook cards and dashboard audiobook actions open the same expanded details sheet without starting playback. The sheet shows cover art, synopsis, series, publisher/publication date, language, pages, ISBNs, rating, reading status, genres, tags, collections, personal notes, and available files where the server provides them. Book information is cached per server account for offline use. Ebook information is available through its long-press options; tapping an ebook still opens the reader.

The Read tab shows authenticated cover thumbnails and lists EPUB, KEPUB, PDF, CBZ, CBR, and CB7 files using bounded server-side search. Tap a book to start reading and keep an account-scoped offline copy. Long-press a book for file choices and download removal. The reader remembers the last file chosen for each book. Use On device to reopen saved files. Download removal preserves local reading positions and notes for the same file revision.

Reader controls start hidden. Tap the middle of the page to show or hide the top and bottom controls; they also hide after six seconds. Tap the left or right quarter of the screen to turn pages, or swipe. Controls overlay the page without changing its layout. Android Back returns to the library even while controls are visible; in PDF selection mode, it cancels selection first. Text selection and PDF zoom gestures remain available. Highlight without a selection shows a temporary hint.

EPUB and KEPUB use [Readium Kotlin](https://readium.org/kotlin-toolkit/3.1.0/), with contents, paging, scrolling, text size, and light, sepia, or dark themes. Bookmark saves a reading location with a name and optional note. Select text and choose Highlight to save a highlighted passage. Notes lists saved passages, offers jumping, editing, and deletion, and disables locations from changed file revisions. Notes and highlights are saved locally for each server account, with up to 500 entries per file. Share annotation explicitly publishes a located passage. Server annotations lists 25 entries per page and supports importing offline copies, editing server notes, and deleting server annotations with confirmation. Sharing checks the file revision. Imported copies and server annotations are managed separately; local edits do not automatically publish, and server deletion retains offline copies. A failed create can have an uncertain result, so check the server list before retrying.

PDF uses Android's native PdfRenderer. CBZ images are read directly from ZIP archives in natural numeric order. CBR and CB7 use BookOrbit's authenticated page-conversion API to prepare an offline ZIP copy. These readers render one page at a time, support pinch zoom and panning, Fit, Zoom +, previous/next pages, page jumps, bookmarks, and page notes. Images are decoded to a bounded size. Encrypted PDFs and image codecs unsupported by the device cannot be read. PDF Highlight area lets you drag a rectangle, add a note, and keep the mark offline or share its page geometry with BookOrbit. Marks follow page zoom and panning. On Android 15 and newer, Select text uses the native PDF selection API: tap a word or drag across a passage, then copy it or save a text highlight and note. Multi-line highlights keep separate rectangles. Scanned pages and older Android versions retain area highlighting.

Sync opens an explicit progress-sharing dialog. Refresh reads the server position; Use server position moves this device; Publish this position queues a durable, account-scoped WorkManager job. The job checks the file revision and re-reads the reviewed server progress before writing, and refuses a changed snapshot. It never automatically publishes reading activity. BookOrbit has no conditional ebook write, so a simultaneous write can still race a user-authorized publish. EPUB sharing includes source CFIs when a location can be resolved, while PDF and comics share page numbers. Source paths are retained through sanitization, and selected text also captures exact range offsets. Incoming CFIs are resolved against the saved EPUB before navigation. Unsupported or ambiguous CFIs fall back to percentage, with a message; the dialog identifies when only a percentage can be published. A publish replaces the server's text position, including its prior CFI. CFIs with temporal/spatial positions and automatic annotation merging are not supported.

Downloads use bounded buffers and the shared limit of two concurrent media transfers. Interrupted downloads restart. Limits are 512 MB per saved book, 20,000 archive entries or pages, 32 MB per expanded resource, and 1 GB total expanded archive size. EPUB scripts and active elements are removed before Readium adds its own controls; remote resources and external links remain blocked. Saved books and credentials are excluded from backup and device transfer. Release packaging remains deferred.

The isolated BookOrbit v3.4.0 instance passed EPUB/PDF/CBZ browsing, authenticated serving, file-size checks, reading-progress writes and reads, EPUB spine discovery, and comic page conversion using synthetic files. Progress tests restored their initial values. The synthetic HTTP fixture additionally supplies CBR/CB7 conversion endpoints for client verification.

## API contract

The upstream API contracts are defined by [BookOrbit's shared types](https://github.com/bookorbit/bookorbit/tree/main/packages/types/src) and [server modules](https://github.com/bookorbit/bookorbit/tree/main/server/src/modules). `app/src/main/java/app/bookorbit/community/data/Models.kt` contains the Kotlin wire projections used by this client. Unknown response fields are tolerated. Request fields are explicit because the server rejects unknown DTO fields. No local dependency on the BookOrbit monorepo is required. Audiobook playback requires the server's v2 audiobook manifest API.

| Request                                      | Contract                                                                                                            |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| `POST auth/login`                            | `username`, `password`, `clientKind: native`, `deviceLabel`; reads `user`, `accessToken`, `refreshToken`            |
| `POST auth/refresh`                          | Body refresh token; atomically saves rotated credentials; retries a rejected request once                           |
| `POST auth/logout`                           | Body refresh token; clears local credentials even if revocation fails                                               |
| `POST books/query`                           | `BookQuery`, format and optional readStatus filters, server search and sorting, 30-item pages; displayed page 1 maps to server page 0; reads `BooksPage.items/total/page/size` |
| `GET books/:id`                            | Ebook file IDs, formats, sizes, and content revisions from the existing book detail model                              |
| `GET books/files/:fileId/serve`              | Authenticated EPUB reading content, kept in account-scoped local storage                                               |
| `GET audiobooks/:id/manifest`                | Audiobook manifest v2, with assets ordered by sequence                                                              |
| `GET audiobooks/:id/assets/:assetId/content` | Authenticated, ranged streaming                                                                                     |
| `GET books/files/:fileId/download`           | Download permission enforced by the existing server; UI checks the account permission too                           |
| `GET/PUT audiobooks/:id/playback-state`      | Asset-relative milliseconds, manifest revision, base revision, capture time, and stable operation UUID              |

All paths use `/api/v1`. Access tokens stay in headers. The HTTP client rejects cross-origin credential forwarding and does not follow redirects. Reverse proxies should route the API directly rather than redirecting it. Library ownership and content access remain enforced by the existing backend.

Progress saves occur every five seconds while connected and every ten seconds while offline, on pause, on seeks, and during orderly service shutdown. Abrupt process termination can lose the last interval. Offline work is retried when connectivity returns. A changed manifest returns 412 and needs a fresh download; conflicts return 409 and are never automatically rebased. Download assets are length-checked when the server provides a size. Download requests use identity encoding, Range, and If-Range when a saved strong HTTP ETag is available. The client verifies Content-Range, validators, and lengths before appending or completing an asset. Servers without this support restart unfinished assets. BookOrbit v3.4.0 ignores ranges on its download endpoint and omits ETag, so it uses this safe restart behavior. File integrity hashes, pre-download space estimates, and cleanup of obsolete revisions remain follow-up work.

## iOS parity backlog

Public research on October 18, 2026 found the [official server repository](https://github.com/bookorbit/bookorbit) and [iOS support repository](https://github.com/bookorbit/bookorbit-ios-support), but no public official iOS application source. The [Play Store BookOrbit listing](https://play.google.com/store/apps/details?id=com.bookorbit) names `deranjer` and links to a separate [Android client repository](https://github.com/deranjer/bookorbit-android). No code from that client is used here.

The [official iOS release history](https://github.com/bookorbit/bookorbit-ios-support/blob/main/RELEASES.md) and [App Store listing](https://apps.apple.com/us/app/bookorbit-the-official-app/id6811807346) provide the parity baseline:

1. Finish physical audiobook checks for Bluetooth, calls, battery restrictions, and timer expiry, and add listening sessions. Download recovery and management, bookmarks, per-book speed, and configurable skip intervals are implemented.
2. Extend reader coverage with real-world books, remaining ebook formats, PDF selection on older Android versions, and additional CFI variants. Source CFI progress sharing and explicit cross-device annotation sharing are implemented.
3. Add Read Along, text to speech, Notebook, library organization, requests, uploads, metadata editing, and activity.
4. Build tablet layouts, accessibility coverage, widgets, Android Auto, and a Wear OS companion. These are Android equivalents of the iPad, CarPlay, and Apple Watch experiences.

Acceptance requires tests with large libraries, account switching, expired tokens, interrupted transfers, offline launches, and concurrent progress changes. Audio playback tests must include real multi-file books, battery restrictions, Bluetooth controls, calls, and screen-off use before calling this production-ready.

## Listening preferences and bookmarks

The player has Bookmarks and Skip intervals controls. Bookmarks save the current audio file and position, with an editable name up to 120 characters. Tap a bookmark to seek without changing whether playback is paused. Each book supports up to 500 bookmarks. If its manifest changes, old bookmarks remain visible for renaming or deletion, but cannot seek into different audio.

Playback speed is saved separately for each book. Back and forward intervals offer 5, 10, 15, 20, 30, 45, or 60 seconds, with defaults of 15 and 30. The intervals apply to all audiobooks for that account, including Android media controls. Skips cross file and chapter boundaries when file durations are known. With unknown durations, skips stay in the current file and clamp to its length when available.

Bookmarks, speed, and skip intervals are local to this device and scoped to both server and account. They survive app restarts and download removal. They do not synchronize to BookOrbit or other devices. Production release signing and the update channel remain pending. A signed debug APK is available for phone testing.

On October 20, 2026, the Android 15 emulator verified creating, renaming, deleting, and reopening bookmarks after restarting the app. A bookmark returned from the first file to the second at exactly 0:25 while keeping playback paused. The app restored 1.5× speed and 20-second back / 45-second forward intervals after restarting. Back from the second file at 0:00 landed in the first at 9:40; forward then landed in the second at 0:25. Automated tests cover storage isolation, independent book speeds, invalid input, bookmark limits, download removal, changed manifests, and skip calculations with known and unknown durations.

## Repeatable smoke fixture

```sh
python3 scripts/fixture-server.py --port 4890
adb reverse tcp:4890 tcp:4890
```

Sign into `http://127.0.0.1:4890` with the fixture-only username and password `reader`. It provides synthetic two-part audio, a two-chapter EPUB, a three-page PDF, a three-page CBZ, and converted-comic endpoints, not a real library. The Read tab lists the reading fixtures; its On device view can be exercised with the fixture stopped. Check search, playback while backgrounded, chapters, speed, downloads, and offline relaunch after stopping the fixture. Never deploy the fixture as a BookOrbit server.

For private real-audiobook previews, pass `--book-dir /path/to/private-fixture`. That directory must contain a v2 `manifest.json`, `cover.jpg`, and one `<fileId>.<format>` file per manifest asset. Supported fixture formats are M4B, M4A, and MP3. File responses stream in bounded chunks and support byte ranges. Keep audiobook copies and their metadata outside the repository. Playback progress stays in the test server rather than reaching your production library.
